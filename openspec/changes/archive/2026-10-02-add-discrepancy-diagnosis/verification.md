## What remains unverified

- A quota wait in a live run: no subscription limit was reached. The route, the delays, the reset and the immediate retry after a restart are covered by unit tests with a fake clock only. The classification of real limit messages relies on the patterns in the tests, and a real Codex usage limit followed by the SDK's exit error is fixture-tested only.
- The removal of the scratch copy after a failed or stopped job (the `finally` in the code, not observed; a normal end was observed). A hard kill of the process leaves its scratch copy of about 14 MB in the temporary folder (observed after the kill above).
- Fan-out over more than one cluster in a live run, and the budget gate over queued jobs in a live pool: the live runs had one cluster. Parallel jobs, the pool bound and the gate are unit-tested with a fake runner behind the pooled runner's rules.
- Live `refused`, `invalid_output` and `infra` results from a real CLI, a live `budget_exhausted`, and a live run with `--no-diagnosis`: unit-tested only. A candidate built outside the workflow has no recorded source and is refused (fixture-tested); a successful `--only diagnose` on a candidate that the workflow built was not run live. The kill and resume ran before the last two code changes; the run after them did not repeat it.
- The `.cmd` shim handling of the Claude CLI against a real `npm i -g` install: this machine has no such install; the lookup is unit-tested with a stub file system.
- What a Codex job can read beyond its scratch copy: the sandbox limits writes, not reads, and no probe asked Codex to read outside its folder. Isolation relies on the copy being outside the repository, so a Codex job can still read the rest of the machine; the repository, its history and the thread's logs are not around its working folder.
- The API-key guards against a real API-key sign-in: neither CLI was set up with an API key. The Claude guard was observed passing (`apiKeySource: none`); the Codex sign-in was `chatgpt`.
- That Codex did not load the repository's `AGENTS.md`: the adapter sets `project_doc_max_bytes = 0`, but the Codex event stream does not show which instruction files it read. The Codex sandbox's network restriction: only the write denial was probed.
- A `refuted` or `undecided` live outcome and a live challenger alternative: the live challenger found no alternative.
- The GitHub Actions job runs the new tests only through `workflow:test`; it has not run on GitHub.
