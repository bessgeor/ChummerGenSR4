## Unverified

- Captures on two desktops at once: only one interactive session was available, so no two lanes with distinct host and user pairs could run together. The pool's use of several lanes, the router's sends for several lanes and the shared reading of the lanes' environments are covered by fixture tests only.
- A lane on another machine: the cross-host lock takeover, the agent liveness check against another machine's clock and paths seen at the same location on another machine are covered by fixture tests only. A lane in another session that cannot read the thread's canonical cache or settings overlay path is not tested at all: the workflow does not check these paths, and `AGENTS.md` says they must be readable and writable at the same path in every lane's session (a missing cache folder is created on the lane's machine, so the lanes would stop sharing canonical sides).
- A live Rider dispatch: no Rider instance with an MCP endpoint was running. The adapter's protocol is covered by the fake server tests only.
- A Ctrl+C (rather than a kill) of a workflow while a capture runs on an agent lane, which writes the cancel file: covered by fixture tests only.
- A quota wait: no model job ran in these threads (`--no-diagnosis`).
- Resuming a thread in the older checkpoint format before its triage (refused) and after it (resumed): covered by fixture tests with that format's edges; no thread written in that format was available for a live resume.
- A dead agent found after a long gap in a run (the case of the heartbeat judged after a gap): covered by the fixture test only; the live runs had no such gap.
